# Level 0 확장 체계

이 문서는 공식 Backrooms Wiki의 현재 분류를 참고해 프로젝트 내부 ID와 제작 순서를 정한다. 위키의 명칭·서사·세력·사건을 그대로 복제하는 문서가 아니다.

## 공식 자료에서 확인한 구분

| 범주 | 공식 자료의 예 | 프로젝트에서의 처리 |
| --- | --- | --- |
| 레벨 | Level 0 | `LV-000` |
| 레벨 내부 변형 | arches, pillars, holes, blackout zones, red rooms, layout changes | 같은 `LV-000` 안의 시각·공간 변형. 별도 레벨 번호를 쓰지 않는다. |
| 이름 있는 방/영역 | Manila Room, Red Rooms | 필요할 때 `REG-L0-*` 형태의 희귀 영역으로 관리한다. |
| 번호가 붙은 하위 구역 | Level 0.1, 0.2, 0.3 | 재질, 환경, 진입·이탈 규칙이 충분히 다른 대규모 확장에만 `LV-000.1` 같은 ID를 사용한다. |

공식 위키의 현재 Level 0 문서는 아치, 기둥, 구멍, 정전 구역, 붉은 방, 배치 변화 등을 Level 0 자체에서 나타나는 구조 변화로 설명한다. 반면 Level 0.1은 Level 0 안에 포함된 거대한 별도 구조, Level 0.2는 Level 0과 Level 1 사이의 하위 구역, Level 0.3은 얼음과 저온이 지배하는 하위 구역으로 기술된다.

## 프로젝트 규칙

1. 현재 제작 중인 노란 벽지·카펫·형광등 계열은 모두 `LV-000`이다.
2. 아치, 기둥 밀집, 천장 변화, 부분 정전, 좁은 압축 통로는 `LV-000`의 변형 세트로 만든다.
3. 변형이 등장했다는 이유만으로 `0.1`을 부여하지 않는다.
4. `LV-000.1`은 새로운 시각 DNA, 일관된 환경 규칙, 드문 진입 경계, Level 0으로 돌아오는 규칙을 함께 설계한 뒤 연다.
5. 공식 위키의 “Zenith Station”을 자동으로 프로젝트 정사에 넣지 않는다. 공식 하위 레벨을 직접 각색할지, 번호 체계만 빌린 독자 하위 레벨을 만들지는 별도 결정으로 남긴다.

## 제작 순서

1. Level 0 후보 20장 주기를 완성한다.
2. 마스크, 연결, 클릭 테스트, 모바일 터치 영역이 안정적인지 검증한다.
3. Level 0 내부 변형 세트를 소량 도입해 생성 프롬프트가 시각적 다양성을 안정적으로 통제하는지 확인한다.
4. 그다음 `LV-000.1` 설계 문서를 작성한다. 최소 요구 항목은 시각 DNA, 입구 문양/경계, 진입 확률, 내부 경로 규칙, 복귀/이탈 규칙, 고유 위험도다.
5. 0.1의 첫 이미지는 기존 Level 0의 확정된 희귀 경로에서만 생성한다.
